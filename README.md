# 基于 RAG 的知识库智能问答 Web 应用

一个全栈 AI 项目：把私有学习资料（PDF / Markdown / TXT）做成可检索的知识库，进行**带引用溯源、能流式输出、支持多轮对话**的智能问答；知识库以外的问题会主动拒答，减少大模型幻觉。项目还包含一套可复现的**评测体系与检索参数对比实验**，并实现了重排序（Rerank）与工具调用（Function Calling）两个加分能力。

- 后端：Python + LangChain + FastAPI（SSE 流式）
- 大模型：阿里云百炼 · 通义千问 `qwen-plus`（生成）、`qwen3.7-text-embedding`（向量化）、`gte-rerank-v2`（重排序）
- 向量库：Chroma（本地持久化）
- 前端：原生 HTML / CSS / JavaScript（单文件、响应式，适配 PC 与移动端）

## 功能特性

- **文档入库**：目录加载 PDF / TXT / MD，递归字符切片，调用 Embedding 模型向量化后存入 Chroma（11 份资料、约 2775 个切片、1024 维向量）。
- **RAG 问答**：用户提问 → 向量检索 Top-k 相关片段 → 拼装提示词 → 通义千问生成答案，答案末尾以 `[1][2]` 标注引用来源。
- **边界拒答**：基于相似度阈值 + 提示词约束，知识库覆盖不到的问题（天气、汇率、菜谱等）回答"知识库中没有相关信息"，不凭空编造。
- **SSE 流式输出**：后端用 FastAPI 的 StreamingResponse 以 Server-Sent Events 逐字返回，前端实时打字机效果。
- **多轮对话记忆**：滑动窗口保留最近 4 轮（8 条）历史，模型能听懂"它""第二个"这类指代。
- **评测体系**：内置 50 条评测集（35 应答 / 15 拒答），自动跑批并生成 Excel，用公式统计答案正确率、正确拒答率、引用命中率。
- **参数对比实验**：固定 20 题做控制变量，对比召回数量 k=2/3/5 与 Rerank 方案，量化各配置效果。
- **重排序 Rerank**：接入 `gte-rerank-v2`，实现"向量粗排 → 重排序精排 → 生成"两段式检索并做 A/B 对比。
- **Function Calling**：用 `bind_tools` 给模型挂载计算器工具，模型遇到算术题自主决定调用工具、程序执行后回传结果再作答，跑通 Agent 工具调用闭环。

## 技术架构

```
浏览器 (HTML/CSS/JS)
   │  HTTP / SSE
   ▼
FastAPI 后端 (app.py)
   │  组装 {问题, 历史, 检索片段}
   ▼
LangChain RAG 链（提示词模板 → 检索器 → 大模型）
   ├── Chroma 向量库（文档切片的向量 + 原文/来源元数据）
   └── 通义千问 qwen-plus（OpenAI 兼容接口）
```

核心链路：**文档加载 → 递归切片 → 向量化入库（离线）**；**提问 → 检索（可选 Rerank）→ 拼 Prompt → 流式生成（在线）**。

## 快速开始

1. 环境：Python 3.11，克隆仓库后安装依赖：
   ```bash
   pip install -r requirements.txt
   ```
2. 申请[阿里云百炼](https://bailian.console.aliyun.com/) API Key，在 `backend/` 下新建 `.env`：
   ```
   DASHSCOPE_API_KEY=sk-你的密钥
   ```
3. 把知识库文档（PDF / TXT / MD）放入 `backend/data/`，在 `backend/` 目录执行入库：
   ```bash
   python ingest.py
   ```
4. 启动后端：
   ```bash
   python app.py
   ```
5. 浏览器访问 `http://127.0.0.1:8000` 即可提问。

> `.env`、`chroma_db/`、`data/` 原始资料与虚拟环境均已在 `.gitignore` 中忽略，克隆后需自行配置密钥并重新入库。

## 评测与优化（真实实测数据）

**1）50 题评测集（35 应答 / 15 拒答）**

| 指标 | 结果 |
| --- | --- |
| 答案正确率（应答类） | **91.4%（32/35）** |
| 正确拒答率（拒答类） | **80.0%（12/15）** |
| 引用命中率 | **94.3%（33/35）** |

**2）检索参数控制变量实验（固定 20 题：15 应答 + 5 拒答）**

| 配置 | 应答正确(/15) | 拒答正确(/5) | 总正确率(/20) |
| --- | :-: | :-: | :-: |
| k=2 | 12 | 3 | 75% |
| k=3（基线） | 12 | 4 | 80% |
| **k=5** | **15** | **4** | **95%** |
| Rerank（粗 10 → 精 3） | 13 | 3 | 80% |

得到的结论：

- 多个 bad case 的根因是**召回覆盖不足**（答案片段存在但没被召回），把 k 从 3 调到 5 后，正确率由 80% 提升到 **95%**，并已将线上检索默认值改为 k=5。
- **Rerank 并非银弹**：在本项目这种"小语料 + 切片已较细"的场景下，精排只保留 3 段反而可能丢掉需要的章节，效果不如直接调大 k；Rerank 更适合候选多、噪声大的大规模语料。
- 纯算术类越界问题在所有检索配置下都答错，说明这类"模型用自身能力越界"的问题要靠**提示词边界约束 / 工具调用**解决，而不是检索参数——这也是补做 Function Calling 的原因。
